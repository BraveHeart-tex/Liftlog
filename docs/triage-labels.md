# Triage labels

Use these GitHub labels when a workflow refers to the corresponding triage role. Each
ticket gets one category label, one state label and at least one area label.

| Label           | Apply when                                                                                                   |
| --------------- | ------------------------------------------------------------------------------------------------------------ |
| bug             | Category: something is broken.                                                                               |
| enhancement     | Category: new feature or improvement.                                                                        |
| ui              | Area: screens, components, sheets, navigation, UI copy.                                                      |
| data            | Area: SQLite, Drizzle schema, repositories, backup and export.                                               |
| native          | Area: Android/iOS native code, Expo modules, config plugins, OS integrations.                                |
| tooling         | Area: release, CI, build scripts and agent tooling.                                                          |
| needs-triage    | Maintainer evaluation is needed.                                                                             |
| needs-info      | Progress depends on missing reporter information.                                                            |
| ready-for-agent | Scope and acceptance criteria are explicit, required context is linked, and blocking questions are resolved. |
| ready-for-human | Implementation requires human judgment, access or intervention.                                              |
| wontfix         | A decision has been made not to action the issue.                                                            |

The `wayfinder:*` labels belong to the `/wayfinder` workflow in
[issue tracker](agents/issue-tracker.md#wayfinding-operations).
